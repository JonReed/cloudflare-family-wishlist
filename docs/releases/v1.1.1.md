# Family Wishlist v1.1.1

Clearer installation and update instructions, easier family sharing, and fixes for restoring a
family member's access. Your existing website address and family data stay in place.

## What's changed

- Installation and update guides use numbered steps, copyable commands, direct dashboard links and
  checks written for people who have never used Cloudflare. Windows command execution is fixed.
- Choose [manual updates](../MANUAL_UPDATES.md) or [automatic updates](../AUTOMATIC_UPDATES.md).
  Manual mode is the default; automatic checks require an explicit opt-in. Both follow published
  releases. Initial setup now downloads released code too, instead of the development branch.
- Share one or several family lists from **Manage → Sharing**. Existing single-list viewing links
  continue to work. Sharing controls and the Manage menu are easier to find.
- Removing a family member hides their list and pictures from family and public viewing links while
  preserving their wishes. Adding the same email again restores their existing list after admission
  succeeds. Copying sign-in details is fixed.
- Family members can use their Gravatar photo. Photos stay out of public viewing links; initials
  remain available when there is no photo. Profile navigation is clearer.
- The footer reads the installed version from the release metadata.

## Updating an existing installation

Start with [Choose how to update](../UPDATES.md). The original standard setup required manual
updates. Publishing this release does not switch existing installations to automatic updates.

- To keep choosing when to update, follow [the manual update guide](../MANUAL_UPDATES.md).
- To receive future releases automatically, follow [automatic update setup](../AUTOMATIC_UPDATES.md)
  and verify the first update before enabling the schedule.

The update uses your existing website, database and sign-in settings. Keep the saved installation
settings from the original setup and make a recovery point before updating. Do not create a new
database or discard household changes to get past a failed update.

This release adds migration `0013_family_share_links.sql`. The supported deploy command,
`npm run deploy:production`, applies it before publishing the app. Existing installations using a
different deploy command must follow the guide's build settings before enabling future updates.
No new runtime secret is required. The build token needs permission to update D1 as explained in
the update guide. A failed deployment does not undo a migration that already succeeded.

guarantee. Verify your first automatic run using the setup guide.
