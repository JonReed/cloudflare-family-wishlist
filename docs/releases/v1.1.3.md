# Family Wishlist v1.1.3

Fixes the persistent cookie strip introduced in v1.1.2. Cookie information now lives in the footer.

- The short notice appears once per browser. It remembers that it was shown automatically, without
  asking anyone to accept cookies or click an acknowledgement. Close hides it immediately if wanted.
- **Cookies & privacy** stays in the footer so the full explanation can be reopened at any time.
- Signed-in pages and shared links use the same browser preference. With blocked storage or without
  JavaScript, the permanent disclosure remains available without a repeating introduction.
- No cookie strip appears above the page header.

The display preference is a fixed value stored only in the browser. It contains no visitor identifier
and is not sent to the server. Clearing site data lets the introduction appear again.

There are no additional database migrations, secrets or setup changes since v1.1.2. If upgrading from
an earlier version, also read the
[v1.1.2 upgrade notes](https://github.com/JonReed/cloudflare-family-wishlist/releases/tag/v1.1.2).
Use your existing [update method](https://github.com/JonReed/cloudflare-family-wishlist/blob/v1.1.3/docs/UPDATES.md).

Verification covers the full quality and dependency-audit gates, desktop/mobile Chrome layouts,
repeat visits, footer disclosure, navigation, blocked storage and JavaScript-free guest forms.
The release workflow repeats the required gates before advancing `stable`.
